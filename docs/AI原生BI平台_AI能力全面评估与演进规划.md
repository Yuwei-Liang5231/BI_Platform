# AI 原生 BI 平台 · AI 能力全面评估与演进规划

> 评估日期：2026-09-22（AI 能力扩展 P1/P2/P3 三批交付并验收通过后）
> 评估范围：平台完善度 + AI 作用发挥度（基于代码事实，非功能清单自评）
> 结论摘要：**平台工程与口径扎实；AI 九域覆盖 9/9 已完成，但价值约发挥 40%——
> 集中在「被动应答」「事后解释」层，主动洞察近乎空白，行动编排与组织记忆为零。**

---

## 一、评估方法

不看"有没有接 AI"，而是按 **AI 降低的是哪一类成本** 分层（L1~L5），
并逐项以代码事实核对（是否存在调度、是否回流、是否被下游消费），
避免"功能已上线即视为价值已达成"的自评偏差。

| 层级 | 定义 | 用户感受 |
|---|---|---|
| L1 | 被动应答：人提要求，AI 作答 | 我点一下，它帮我写/帮我配 |
| L2 | 事后解释：数据先算出，AI 再讲清 | 数字有了，它告诉我发生了什么 |
| L3 | 主动洞察：AI 自己发现并推送 | 我没问，它先告诉我出事了 |
| L4 | 行动编排：AI 给"下一步"并串起流程 | 它不只说，还带我往下查 |
| L5 | 组织记忆：人工修正回流，越用越准 | 它记得我们公司的口径和习惯 |

## 二、平台完善度评估（非 AI 维度）

### 2.1 强项（同类自研平台中少见）

- **口径单一真相**：指标编译器 → DuckDB 执行 → LRU 缓存 → 看板/问数/报告/导出
  同参同键，跨模块数字一致（B2/B3/B9 契约支撑）。
- **真实可用的分析链路**：异动检测（3σ + 同比星期几基准 + 要紧度）→ 归因下钻
  （多层维度拆解、贡献占比可手算对账）→ 报告（模板 + 存档 + 叙述）。
- **工程质量**：447 项自动化测试、契约分级冻结、软删留痕、口径变更存档与影响清单、
  项目/主题隔离（B9.3）、模板幂等导入。
- **AI 安全红线**：通用算写分离引擎（LLM 只见 `{{ref:KEY}}`、数字服务端回填）、
  三道审计（未知 ref / 裸数字含中文数量词 / 畸形占位符）、章节级降级、
  权限同源（受限指标源头过滤，不泄露名称）。

### 2.2 缺口（产品化/企业级）

| # | 缺口 | 影响 | 证据 |
|---|---|---|---|
| N1 | **无任何定时调度**（无 apscheduler/celery/cron） | 报告要手动生成、异动要人进页面才扫描；"看板不等人来找问题"未闭环 | 全仓无调度依赖与任务 |
| N2 | 通知仅站内，无邮件/企微 | 离线收不到异动 | 无 smtplib/邮件通道 |
| N3 | 无操作审计日志 | 谁改口径、谁导出数据无留痕，合规硬伤 | 无 audit_log 相关模型 |
| N4 | 项目级权限未做（B15 挂账） | 权限只到指标可见性，跨项目靠项目隔离 | 契约明确"项目级权限留 B15" |
| N5 | 无血缘/影响面、无使用热度、无数据质量常态化监控 | 改数据集影响哪些指标靠人工判断；质检按需现算 | 无血缘表；质检为即时接口 |

## 三、AI 作用层级评估（核心结论）

| 层级 | 状态 | 已落地功能 |
|---|---|---|
| L1 被动应答 | **已满配** | 问数意图解析（越纲丢弃防幻觉）、AI 帮写口径、AI 字段语义标注 |
| L2 事后解释 | **主力** | 看板 AI 速览、AI 异动假设（三态降级）、归因根节点 AI 解读、报告叙述四章节 |
| L3 主动洞察 | **近乎空白** | 仅"问数动态异动推荐"一条（读已落库通知，排推荐首位） |
| L4 行动编排 | **空白** | 无追问路径推荐、无多指标联动归因 |
| L5 组织记忆 | **空白** | 无人工修正回流、无口径讨论沉淀、无 AI 质量观测 |

**关键论断**：AI 目前主要降低「理解成本」，尚未降低「发现成本」（要人去点）与
「决策成本」（不给下一步）。九域覆盖 ≠ 价值最大化。

### 3.1 六大实锤差距（均以代码事实核对）

1. **主动洞察空白**：无调度 → 异动检测、AI 速览、假设生成全靠人点按钮；
   真正主动的仅问数动态推荐一条。
2. **语义标注是孤岛**：`column_semantics` 已落库，但**下游零消费**——
   问数意图解析、建模建议、看板速览、帮写口径均未使用这批人工确认的语义，
   AI 记忆未打通（标注完就没下文）。
3. **无反馈与观测闭环**：AI 输出好坏不回流（无采纳/纠正），审计命中率、
   降级率、延迟、Token 成本无统计；线上 AI 质量处于"盲"状态
   （排查归因解读失败时需临时补日志才定位）。
4. **单指标思维**：异动假设、归因解读均只针对单一指标；缺"多指标联动归因"
   （GMV 跌 → 是流量还是客单价 → 哪些指标同时异常）。
5. **只描述、不给下一步**：中性陈述是防幻觉的正确设计，但也压住了价值上限；
   缺「AI 建议 + 人确认 + 可追溯」的行动层。
6. **看板仍为纯展示 + 手动速览**：无常驻"本期最值得关注的 N 件事"洞察条。

## 四、演进规划（三梯队）

### 第一梯队 — AI 从 L2 跃到 L3（价值最大）

| # | 事项 | 层级 | 说明 |
|---|---|---|---|
| A1 | 定时洞察任务 + 订阅推送 | L3 | 每日自动扫描 → 生成假设 → 站内/邮件推送负责人（顺带报告定时生成） |
| A2 | 常驻 AI 洞察条 | L3 | 看板/总览自动呈现本期最值得关注的 2~3 件事（含自动归因） |
| A3 | **语义标注下游打通** | L3/L5 | 问数、建模建议、帮写口径消费 `column_semantics` |
| A4 | 多指标联动归因 | L4 | 一指标异动时自动找同期同向/反向关联指标并给传播路径 |

### 第二梯队 — AI 质量与记忆（长期可信）

| # | 事项 | 层级 | 说明 |
|---|---|---|---|
| B1 | **AI 反馈闭环** | L5 | 每条 AI 输出加"有用/无用 + 修正"，bad case 入库 |
| B2 | AI 观测面板 | L5 | 审计命中率、降级率、延迟、Token 成本、常见失败原因 |

### 第三梯队 — 平台完善度（非 AI）

| # | 事项 |
|---|---|
| C1 | 报告/异动定时调度 + 订阅（含邮件/企微） |
| C2 | 操作审计日志（合规） |
| C3 | 项目级权限（B15） |
| C4 | 血缘影响面 + 数据质量监控常态化 + 使用热度观测 |

### 本批（P4）范围

按 ROI 排序，"最划算的下一步"是 **A3 + B1**（成本低，却能让现有所有 AI 功能的
准确率随使用时间上升——这是「AI 原生」与「接了个大模型」的分水岭）：

- **P4-1 语义标注下游打通**：AI 帮写口径、建模建议消费人工确认的列语义。
- **P4-2 AI 反馈闭环**：新增反馈表与接口，各 AI 输出区加"有用/无用 + 修正"，
  并提供质量统计（按功能维度的赞踩、降级率、最近 bad case）。

## 五、P4 交付记录（2026-09-22）**P4-1 语义标注下游打通**（让人工确认的语义影响 AI 输出，标注产生复利）
- `domain/ai/calc_notes.py`：口径助手读取 `column_semantics`，作为
  `confirmed_semantics` 强约束传给 LLM（system prompt 明确"必须一致、不得矛盾"），
  响应新增 `confirmed_semantics` 字段；无标注时为空串，行为与 P1 完全一致（零退化）。
- `domain/ai/semantic_annotations.py`：`suggest_annotations` 把已落库语义回传，
  提示词要求新增第 5 条——同列建议不得与人工确认语义矛盾、术语风格看齐。
- 前端 MetricAdmin：生成口径后提示"已结合人工确认的字段语义「…」生成建议"。

**P4-2 AI 反馈闭环**（AI 质量可观测、可回流）
- 新增表 `ai_feedbacks`（user_id / project_id / kind / target / rating /
  correction / created_at；B10 规矩挂 project_id）。
- `POST /ai/feedback`：kind 白名单（6 类）+ rating up/down 校验，非法不入库且
  不报错（返回 `recorded:false`），反馈失败不影响任何 AI 主流程。
- `GET /ai/feedback/summary`（admin）：按功能聚合的赞/踩/差评率 + 最近 20 条
  bad case（含人工修正文本与用户）。
- 前端：新组件 `components/business/AiFeedback.vue`（这条 AI 结论：有用 / 无用 →
  展开修正输入 → 提交 → 致谢态；乐观置位、提交失败静默），挂到
  Dashboard 速览、MetricDetail 异动假设与归因解读、MetricAdmin 帮写口径四处。

**验证**：新增 4 个用例（反馈往返与概览、非法 kind、非 admin 403、语义下游消费）；
全量 **451 passed**（基线 447 + 4）；build:dev 11.8s 通过。

## 六、P5 交付记录（2026-09-22，第一梯队 A1 落地）

**A1 定时洞察 + 站内推送**（AI 从 L2 事后解释跃到 L3 主动洞察的核心一步）：

- **每日洞察服务** `domain/insight/service.py`：`run_daily_insight`——对每个项目
  自动扫描（复用 detect_for_project，opt-in 语义不变）→ 取要紧度 TOP N
  （默认 3，`ai_insight_top_n` 可调）→ 生成 AI 假设（复用 build_anomaly_hypothesis，
  权限上下文 = 项目内 admin；失败/无 LLM → 规则文案降级）→ 落 `ai_insights`
  表（同 项目+日期+指标+方向 去重，重复执行幂等）→ 以 `kind="insight"`
  站内通知推送对该指标可见的全部活跃用户（权限同源，共用
  auth.build_user_hidden_map 批量映射）。
- **零依赖轻量调度器** `infra/scheduler.py`：FastAPI lifespan 启动 asyncio
  循环，每 30 分钟巡检，到达 `ai_insight_hour`（默认 8 点）且当日未跑则在线程池
  执行（同步 LLM 调用不卡事件循环）；进程重启当日补跑；失败只记日志不阻塞主服务；
  `ai_insight_enabled=false` 可整体关闭。
- **手动触发**：`POST /ai/insight/run`（admin）——验收/补跑入口，幂等。
- **通知升级**：notifications 表加 `kind` 列（存量默认 anomaly，幂等迁移），
  API 返回 kind；前端铃铛对洞察通知显示「每日洞察」橙色标签。
- **验证**：`tests/test_insight.py` 3 用例（落库+推送+幂等、手动端点+403、
  kind 区分）；全量 **454 passed**；build:dev 13.7s 通过。
- 已知边界：外部渠道（邮件/企微）属 C1；洞察只覆盖「显式开启异动检测」的
  指标（与总览页同一 opt-in 语义，避免全量扫描超时）。

## 八、P7 交付记录（2026-09-23，第一梯队 A4 落地，第一梯队清零）

**A4 多指标联动归因**（评估六大差距中「单指标思维」的收口：一指标异动时自动找
同期关联指标并给传播路径假设，AI 从单指标解释跃到经营视角联想）：

- **确定性分析** `domain/ai/metric_linkage.py`：目标指标取「统计区间 + 等长前区间」
  日序列（口径/权限同源 compute_metric_series）；候选 = 同项目 active、当前用户
  可见（build_user_hidden_map）的其余指标（限量扫描 MAX_SCAN=12，按 id 稳定）；
  对齐日值算 **Pearson 相关系数**（|r| ≥ 0.6 才算联动，对齐不足 5 对不判定，
  零方差排除），按「本期窗口合计 vs 前等长窗口合计」判定候选方向与变化幅度；
  按 |r| 倒序 TOP N（默认 3）。r 是统计量非指标值，按 z-score 同款例外保留
  2 位小数展示。
- **AI 传播假设**：算写分离——r、方向、变化幅度全部服务端预格式化进 ref_table，
  LLM 只见 {{ref:KEY}}，prompt 强制「可能」措辞不编造因果；1~3 候选句逐句审计；
  无 LLM/失败 → interpretation=null + reason，规则句 rule_text 恒可展示，
  候选清单本身是确定性结果不受降级影响。
- **接口** `GET /ai/metric-linkage?metric_id&start&end`（登录用户；软删指标
  显式报错；_AI_KINDS + metric_linkage）。
- **前端** `components/business/MetricLinkage.vue`：自动加载、红涨绿跌三角、
  候选行（方向 ▲/▼ + 名称点击跳详情 + 本期变化 % + 同向/反向标签 + r 值）、
  AI 解释 + AiFeedback、零阻塞降级；两处集成——指标详情页「AI 异动假设」卡内
  （检测到异动自动出现）与经营总览异动卡片「关联指标」按钮展开（自然周窗口
  与归因同口径，weekWindow 抽取共用）。
- **验证**：`tests/test_linkage.py` 3 用例（线性候选 r=1.0 命中 + 无关/零方差
  排除 + 降级、受限候选隐藏、软删目标报错）；全量 **460 passed**（基线 457 + 3）；
  build:dev 7.0s 通过。
- 验收口径：详情页选带异动的指标 → 异动假设卡下方出现联动清单（同项目内
  真正相关的指标才出现，宁缺毋滥）；总览异动卡片点「关联指标」展开同样内容；
  受限用户看不到受限候选；无 LLM 时显示规则句「同期有 N 个指标与本指标联动：…」。
- 已知边界：相关 ≠ 因果，AI 措辞已强制「可能」；候选扫描上限 12 个（指标很多时
  按创建顺序取前 12），后续可按使用热度优先；窗口为调用方给的统计区间
  （详情页=所选区间，总览=异动自然周）。

**验收修复（2026-09-23 用户实测）**：详情页选**单日区间**（如 09-20~09-20）时
看不到联动清单——单日窗口对齐日值 ≤2 对，相关系数永远算不出，且组件对空结果
